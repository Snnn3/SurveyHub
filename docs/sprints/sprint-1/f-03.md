## 4. Contract F-03: Survey Taking, Submission and Response Rules

### 4.1 Scope and linked requirements

- **Requirements:** FR-07, FR-08, FR-09
- **Business rules:** BR-01, BR-02, BR-03, BR-05, BR-08
- **NFRs:** NFR-PERF-01, NFR-DATA-01
- **Feature:** F-03
- **Dependencies:** F-01, F-02
- **Sprint:** 1

### 4.2 Behaviour

- A respondent sees only published surveys.
- `hasSubmitted` is computed from `ResponseClaim`.
- The form endpoint returns ordered questions and options for a published survey.
- Submission validates the whole payload before writing.
- The response, answers, selected options and claim are written in one transaction.
- A second submission is rejected with `409 DUPLICATE_SUBMISSION`; exactly one response remains.
- The receipt endpoint returns only the caller's own response.
- In Sprint 1, every authenticated respondent is eligible. The `SurveyEligibility` table is present
  but empty; Sprint 2 adds allowlist management.

### 4.3 UI behaviour

**`/surveys`**

- Cards for published surveys with title, description and a status badge:
  - "Not submitted" → Start survey
  - "Completed" → View receipt, disabled start
- Empty state if no published surveys exist.
- Loading skeleton.

**`/surveys/:id/take`**

- Renders questions in `orderIndex` order.
- Single-choice: radio group.
- Short text: textarea with a character counter and a 2,000-character limit.
- Required questions show a visible "Required" marker.
- Submit disabled while pending.
- Client validates required answers for convenience; server revalidates.
- `409` shows "You have already submitted a response to this survey."
- `400 SURVEY_NOT_ACCEPTING_RESPONSES` shows "This survey is no longer accepting responses."
- `400 MISSING_REQUIRED_QUESTIONS` highlights the missing questions.

**`/surveys/:id/confirmation/:responseId`**

- Green confirmation card with response id and submitted time.
- A "View receipt" action re-fetches the persisted receipt from the API, proving persistence.

### 4.4 Data specification

Tables: `survey_responses`, `answers`, `answer_options`, `response_claims`.

- `survey_responses.respondent_id`: nullable; non-null in Sprint 1 identified mode.
- `survey_responses.submitted_at`: server time.
- `response_claims(survey_id, user_id)` unique.
- `answers(response_id, question_id)` unique; one answer row per question per response.
- `answer_options(answer_id, option_id)` unique.
- `answers.text_value`: nullable, ≤10,000 characters in the forward-compatible schema; Sprint 1 short-text validation remains ≤2,000 characters.
- `answers.number_value`: nullable integer; Sprint 2 rating is 1–5 and integer questions use configured bounds.
- `answers.date_value`: nullable date-only value for Sprint 2 date questions.

Submission transaction:

```text
BEGIN
  verify survey exists, is PUBLISHED, and (Sprint 2) is before closesAt
  verify role is RESPONDENT and eligibility if configured
  insert response_claim (unique survey_id + user_id)
  insert survey_response (respondent_id = current user)
  insert answers and answer_options
COMMIT
```

If the claim insert fails with `P2002`, return `409` and roll back. No partial response is stored.

### 4.5 API specification

All routes require `RESPONDENT`.

#### GET `/api/surveys/active`

Success `200`:

```json
{
  "success": true,
  "data": [
    {
      "id": "<uuid>",
      "title": "CPE 334 Midterm Feedback",
      "description": "Please give honest feedback.",
      "status": "PUBLISHED",
      "questionCount": 2,
      "hasSubmitted": false
    }
  ]
}
```

Only `PUBLISHED` surveys. `hasSubmitted` is true when a claim exists for the current user.

#### GET `/api/surveys/:id/form`

Success `200`: survey metadata plus ordered questions and options.

Errors: `400 SURVEY_NOT_ACCEPTING_RESPONSES` for draft/closed; `404 NOT_FOUND`.

#### POST `/api/surveys/:id/responses`

Request:

```json
{
  "answers": [
    { "questionId": "<uuid-1>", "selectedOptionIds": ["<uuid-option>"] },
    { "questionId": "<uuid-2>", "textValue": "More lab time, please." }
  ]
}
```

Rules:

- Each question appears at most once. Duplicate question ids → `400 INVALID_ANSWER`.
- Unknown question ids → `400 INVALID_ANSWER`.
- Single-choice: exactly one selected option, belonging to that question.
- Short text: non-empty when required; trimmed; ≤2,000 characters.
- Required questions missing → `400 MISSING_REQUIRED_QUESTIONS` with the missing ids.
- A question must not mix option and text/number values.
- Optional unanswered questions may be omitted.

Success `201`:

```json
{
  "success": true,
  "data": {
    "responseId": "<uuid>",
    "surveyId": "<uuid>",
    "submittedAt": "2026-11-06T14:30:00.000Z",
    "message": "Survey response successfully recorded."
  }
}
```

Errors:

- `409 DUPLICATE_SUBMISSION`
- `400 SURVEY_NOT_ACCEPTING_RESPONSES`
- `400 MISSING_REQUIRED_QUESTIONS`
- `400 INVALID_ANSWER`
- `403 FORBIDDEN_ROLE`
- `403 NOT_ELIGIBLE` (Sprint 2)
- `404 NOT_FOUND`

#### GET `/api/surveys/:id/responses/:responseId`

Success `200`: the caller's own receipt with answer content and `submittedAt`.

Errors:

- `403 FORBIDDEN_CROSS_RESPONSE_ACCESS` when the response belongs to another user.
- `403 FORBIDDEN_ROLE` for an owner account.
- `404 NOT_FOUND` when the response id does not exist for that survey.

### 4.6 Acceptance criteria

| AC | Observable outcome |
|---|---|
| **AC-F03-01** | `GET /api/surveys/active` returns published surveys only and a correct `hasSubmitted` flag. |
| **AC-F03-02** | `GET /api/surveys/:id/form` returns ordered questions and options for a published survey. |
| **AC-F03-03** | A valid submission returns `201` and persists one response, its answers, selected options and claim in PostgreSQL. |
| **AC-F03-04** | A second submission returns `409 DUPLICATE_SUBMISSION`; exactly one response exists. Under two concurrent submissions, one succeeds and one gets `409`. |
| **AC-F03-05** | Submitting to a `DRAFT` or `CLOSED` survey returns `400 SURVEY_NOT_ACCEPTING_RESPONSES`. |
| **AC-F03-06** | Missing required answers return `400 MISSING_REQUIRED_QUESTIONS` with the missing question ids. |
| **AC-F03-07** | Wrong answer type, a foreign option, duplicate question ids or text over 2,000 characters returns `400 INVALID_ANSWER`. |
| **AC-F03-08** | A respondent requesting another respondent's receipt gets `403 FORBIDDEN_CROSS_RESPONSE_ACCESS` with no answer data. |
| **AC-F03-09** | A `SURVEY_OWNER` token submitting a response gets `403 FORBIDDEN_ROLE`. |
| **AC-F03-10** | The respondent can retrieve their own persisted receipt after a reload, with the same answers and timestamp. |
