### 3.2 Lifecycle

```text
DRAFT ──publish──→ PUBLISHED ──close──→ CLOSED
  │                                        │
  └──delete (draft only)                   └── terminal
```

Allowed operations:

| Current status | Full structure update (PUT) | Metadata update (PATCH) | Delete | Publish | Close |
|---|---|---|---|---|---|
| DRAFT | Yes | No; use the existing full draft editor | Yes | Yes, if structure valid | No |
| PUBLISHED | No | Yes; title and description only | No | No | Yes |
| CLOSED | No | No | No | No | No |

The accepted Sprint 1 v4 baseline allowed no updates after publication. Proposed Lab 7 amendment
v5 adds only the metadata operation shown above; it does not unlock structural edits.

Any other transition returns `400 INVALID_STATE_TRANSITION`.

### 3.3 UI behaviour

**`/owner/surveys`**

- Lists only the owner's surveys with title, status badge, question count and response count.
- Actions depend on status:
  - DRAFT: Edit, Delete, Publish, View summary
  - PUBLISHED: Edit details, Close, View summary
  - CLOSED: View summary
- Empty state: "No surveys yet. Create your first survey."
- Loading skeleton while fetching.

**`/owner/surveys/new` and `/owner/surveys/:id/edit`**

- Title (required, 1–120 characters), description (optional, ≤2,000 characters).
- Dynamic question list:
  - Type: single-choice or short text (Sprint 1).
  - Required toggle.
  - Prompt (1–500 characters).
  - For single-choice: 2–20 option labels, each 1–200 characters.
  - Reorder with up/down buttons.
  - Remove question with confirmation.
- Client prevents obvious invalid publish, but the server revalidates.
- Publish button shows a validation summary if the structure is invalid.
- Close opens a confirmation dialog.

**/owner/surveys/:id/metadata** (Lab 7 amendment v5)

- Available only to the owner of a PUBLISHED survey.
- Shows only title and respondent-facing description fields; it has no question, option, status or
  lifecycle controls.
- Saving calls PATCH /api/surveys/:id/metadata. A later respondent form load shows the updated
  title and description.
- Draft editing continues to use /owner/surveys/:id/edit.

**`/owner/surveys/:id/summary`** — defined in F-04.

### 3.4 Data specification

Tables: `surveys`, `questions`, `options`.

- `surveys.title`: 1–120 characters (SQL check).
- `surveys.status`: enum, default `DRAFT`.
- `surveys.mode`: enum, default `IDENTIFIED`.
- `surveys.owner_id`: FK to `users.id`, `onDelete: Restrict`.
- `published_at`, `closed_at`: nullable timestamps.
- `questions.prompt`: 1–500 characters (SQL check).
- `questions.question_type`: enum.
- `questions.is_required`: default true.
- `questions.order_index`: non-negative; ordered by `orderIndex, id`.
- `options.label`: 1–200 characters; unique per question.
- `options.order_index`: ordered by `orderIndex, id`.

`PUT /api/surveys/:id` replaces the question set in a transaction:

1. Verify owner and `DRAFT`.
2. Validate the full new structure.
3. Delete existing questions (cascades options) and recreate them with stable order.
4. Update title and description.
5. Return the full updated survey.

No migration change is required for Sprint 1 beyond the initial schema.

The Lab 7 metadata update writes only surveys.title and surveys.description. It does not delete
or recreate questions or options, and it does not update answers, response rows, counts, publishedAt,
closesAt or closedAt. No schema migration is required because these metadata columns already
exist. updatedAt may advance as the normal record update timestamp.

### 3.5 API specification

All routes require `SURVEY_OWNER`.

#### GET `/api/surveys`

Success `200`:

```json
{
  "success": true,
  "data": [
    {
      "id": "<uuid>",
      "title": "CPE 334 Midterm Feedback",
      "status": "PUBLISHED",
      "mode": "IDENTIFIED",
      "questionCount": 2,
      "responseCount": 12,
      "createdAt": "2026-11-05T10:00:00.000Z",
      "updatedAt": "2026-11-05T10:30:00.000Z"
    }
  ]
}
```

Only surveys with `ownerId = currentUser.id`.

#### POST `/api/surveys`

Request:

```json
{
  "title": "CPE 334 Midterm Feedback",
  "description": "Please give honest feedback.",
  "questions": [
    {
      "prompt": "How satisfied are you with the course?",
      "questionType": "SINGLE_CHOICE",
      "isRequired": true,
      "options": [
        { "label": "Very satisfied" },
        { "label": "Neutral" },
        { "label": "Unsatisfied" }
      ]
    },
    {
      "prompt": "What should improve?",
      "questionType": "SHORT_TEXT",
      "isRequired": false
    }
  ]
}
```

Success `201`: the full draft survey, `status: "DRAFT"`.

Errors: `400 VALIDATION_ERROR`, `403 FORBIDDEN_ROLE`.

#### GET `/api/surveys/:id`

Success `200`: full survey with ordered questions and options.

Errors: `403 FORBIDDEN_OWNERSHIP`, `404 NOT_FOUND`.

#### PUT `/api/surveys/:id`

Same body as create. Replaces metadata and questions. Allowed only for `DRAFT`.

Success `200`: updated full survey.

Errors:

- `400 SURVEY_NOT_EDITABLE` — status is `PUBLISHED` or `CLOSED`.
- `400 VALIDATION_ERROR` — invalid structure.
- `403 FORBIDDEN_OWNERSHIP`, `404 NOT_FOUND`.

#### PATCH /api/surveys/:id/metadata (Lab 7 amendment v5)

All requests require SURVEY_OWNER. Only the survey owner may update metadata, and the survey must
still be PUBLISHED at the write. The body is a strict object with one or both of title and
description; at least one must be present. Unknown fields are rejected as a whole.

Example body: { "title": "Course feedback (clarified)", "description": "Please focus on the second half." }

- title, when present, is trimmed, nonblank and at most 120 characters.
- description, when present, is trimmed and at most 2,000 characters. null or an empty string
  clears the description; an omitted property leaves its current value unchanged.
- Success 200: updated survey detail. A subsequent owner detail read and respondent form read
  return the saved title and description.
- 400 VALIDATION_ERROR: blank/over-limit values, an empty body, or any field outside title and
  description. If valid metadata is combined with a forbidden field, nothing is saved.
- 400 SURVEY_NOT_EDITABLE: status is DRAFT or CLOSED. PUT full replacement and DELETE
  remain forbidden for PUBLISHED and CLOSED.
- 403 FORBIDDEN_ROLE, 403 FORBIDDEN_OWNERSHIP, 404 NOT_FOUND.

The service must serialize this update with close and recheck ownership and PUBLISHED status in
the transaction immediately before writing. If close commits first, the metadata update fails and
does not change either field. If the metadata update commits first, close may then proceed.

#### DELETE `/api/surveys/:id`

Success `204` with no body. Cascades questions and options. Allowed only for `DRAFT`.

Errors: `400 SURVEY_NOT_EDITABLE`, `403 FORBIDDEN_OWNERSHIP`, `404 NOT_FOUND`.

#### PATCH `/api/surveys/:id/publish`

Success `200`: status `PUBLISHED`, `publishedAt` set.

Errors:

- `400 INVALID_QUESTION_STRUCTURE` — no questions; a single-choice question has fewer than two
  options; empty prompt; duplicate option labels.
- `400 INVALID_STATE_TRANSITION` — not `DRAFT`.
- `403 FORBIDDEN_OWNERSHIP`, `404 NOT_FOUND`.

#### PATCH `/api/surveys/:id/close`

Success `200`: status `CLOSED`, `closedAt` set.

Errors: `400 INVALID_STATE_TRANSITION` — not `PUBLISHED`; `403 FORBIDDEN_OWNERSHIP`, `404 NOT_FOUND`.

### 3.6 Acceptance criteria

| AC | Observable outcome |
|---|---|
| **AC-F02-01** | `GET /api/surveys` returns only the current owner's surveys, with status and counts. |
| **AC-F02-02** | `POST /api/surveys` creates a `DRAFT` with ordered questions and options, stored in PostgreSQL. |
| **AC-F02-03** | `GET /api/surveys/:id` returns the owner's full survey detail. |
| **AC-F02-04** | `PUT /api/surveys/:id` updates a draft's title, description and questions atomically. |
| **AC-F02-05** | `DELETE /api/surveys/:id` deletes a draft and cascades its structure; no questions or options remain. |
| **AC-F02-06** | Publishing a valid draft returns `200` and sets `status = PUBLISHED` and `publishedAt`. |
| **AC-F02-07** | Publishing an invalid structure returns `400 INVALID_QUESTION_STRUCTURE` and leaves the status `DRAFT`. |
| **AC-F02-08** | Closing a published survey returns `200` and sets `status = CLOSED` and `closedAt`. |
| **AC-F02-09** | A non-owner gets `403 FORBIDDEN_OWNERSHIP` for get, update, delete, publish and close; data is unchanged. |
| **AC-F02-10** | Full structural update (PUT) or deletion of a published/closed survey returns 400 SURVEY_NOT_EDITABLE. Published metadata corrections are governed separately by LAB7-AC-01..04. |
| **AC-F02-11** | Publishing a published/closed survey or closing a draft/closed survey returns `400 INVALID_STATE_TRANSITION`. |

### 3.6.1 Proposed Lab 7 acceptance criteria (Issue #85)

These criteria amend the Sprint 1 contract for the maintenance change. They remain planned until
implementation and test results are recorded under Issue #86.

| AC | Observable outcome |
|---|---|
| **LAB7-AC-01** | An owner updates the title and description of their own PUBLISHED survey through the UI and API. The values persist after reload and appear when a respondent opens the form again. |
| **LAB7-AC-02** | A supplied title is trimmed, nonblank and 1–120 characters; an optional description is at most 2,000 characters and can be cleared. Exact limits pass; blank and over-limit values fail. |
| **LAB7-AC-03** | The metadata endpoint rejects questions, options, mode and lifecycle/ownership fields. A request containing valid metadata plus any forbidden field saves nothing. Question/option IDs and order, existing answers, response count, publishedAt, closesAt and closedAt remain unchanged. |
| **LAB7-AC-04** | A different owner and a respondent cannot edit; CLOSED stays locked. Draft full edits and draft deletion remain available, while published structural edit/delete remain blocked. A close that wins a race prevents a later metadata write. |
